# COMP214 — eCommerce Bookstore Database Setup Guide

This guide explains how to create, populate, reset, and access the COMP214 eCommerce Bookstore database using Oracle SQL Developer and Oracle Autonomous AI Database.

## Part 1 — Create and Seed the Database

### Prerequisites

- Oracle SQL Developer is installed and connected to the team database.
- The database user has permission to create tables, sequences, and indexes.
- The user has sufficient storage quota on the `DATA` tablespace.

Replace `<USERNAME>` with the account that will own the tables.

### Step 1 — Verify Your Connection

Connect using the account designated as the schema owner.

### Step 2 — Create the Database Tables

On an empty worksheet, open and execute:

`COMP214_Create_Tables_v4_2.sql`

This creates the 12 bookstore tables, including their primary keys, foreign keys, and other constraints.

### Step 3 — Populate the Tables

Open and execute:

`COMP214_Master_Seed_v4_2.sql`

This inserts the bookstore sample data and initializes the project sequences.

**Note:** `PRICE_AUDIT` and `EMBEDDING_LOG` are intentionally left empty. Records will be generated by their corresponding database operations.

### Step 4 — Create B-tree Indexes

Open and execute:

`COMP214_Create_Indexes_v4_1.sql`

This creates additional indexes to improve query and join performance.

### Step 5 — Verify the Database

```sql
-- List all bookstore tables owned by the connected account
SELECT table_name
FROM user_tables
ORDER BY table_name;

-- Verify sample data
SELECT COUNT(*) AS total_books FROM books;
SELECT COUNT(*) AS total_reviews FROM reviews;

-- Verify that audit and embedding logs are empty
SELECT COUNT(*) AS audit_records FROM price_audit;
SELECT COUNT(*) AS embedding_logs FROM embedding_log;

-- List sequences
SELECT sequence_name
FROM user_sequences
ORDER BY sequence_name;
```

Expected results after a successful initial seed:

- 12 bookstore tables
- 100 books
- 150 reviews
- 0 price audit records
- 0 embedding log records

## Part 2 — Drop All Tables and Data

**Warning:** The following process permanently deletes all bookstore tables and their data. Back up important work and coordinate with team members before proceeding.
               This script is used to start from a clean slate.

### Step 1 — Connect as the Schema Owner

Use the account that owns the bookstore tables.

### Step 2 — Execute the Reset Script

Open and execute:

`COMP214_Drop_All_Tables_And_Sequences.sql`

The script removes:

- All 12 bookstore tables and their data
- Related primary-key, unique, B-tree, and vector indexes
- Triggers attached to the dropped tables
- All 11 project sequences

Standalone packages, procedures, views, and synonyms are not necessarily removed by this script.

### Step 3 — Verify the Reset

```sql
SELECT table_name
FROM user_tables
ORDER BY table_name;

SELECT sequence_name
FROM user_sequences
ORDER BY sequence_name;
```

The bookstore tables and project sequences should no longer appear.

To rebuild the database, perform **Part 1**.

## Part 3 — Access Another User's Schema

These instructions are for team members who need to work with bookstore tables owned by another Oracle database user.

### Step 1 — Request Database Access

The schema owner or database administrator must grant the required permissions.  The administrator can use:

`COMP214_Full_Team_DDL_Access.sql`

Review the script and replace any usernames or schema references before execution.

**Important:** This script may contain elevated cross-schema DDL privileges. Only authorized administrators should execute it.

### Step 2 — Connect Using Your Own Account

Open Oracle SQL Developer and connect using your assigned database username.

Do not connect using the schema owner's credentials.

### Step 3 — Create Private Synonyms

Open and execute:

`COMP214_Team_Private_Synonyms.sql`

Before execution, verify that the script references the correct shared schema owner.

This creates private synonyms for the bookstore tables and sequences.

The synonyms only need to be created once per user account.

If synonym creation fails with `ORA-01031`, request the `CREATE SYNONYM` privilege from the database administrator.

### Step 4 — Display Synonyms in the Root Tables Folder

In Oracle SQL Developer:

1. Expand your database connection.
2. Right-click the root **Tables** folder.
3. Select **Apply Filter**.
4. Enable **Include Synonyms**.
5. Clear any restrictive filter conditions.
6. Click **OK**.
7. Right-click **Tables** and select **Refresh**.

The shared table synonyms should now appear in the root **Tables** folder, as supported by the SQL Developer version and its navigator settings.

## SQL Script Reference

| Script | Purpose | Execute As |
|---|---|---|
| `COMP214_Create_Tables_v4_2.sql` | Creates the 12 bookstore tables | Schema owner |
| `COMP214_Master_Seed_v4_2.sql` | Populates tables and initializes sequences | Schema owner |
| `COMP214_Create_Indexes_v4_1.sql` | Creates B-tree indexes | Schema owner |
| `COMP214_Create_Vector_Indexes_v4_1.sql` | Creates HNSW vector indexes | Schema owner |
| `COMP214_Drop_All_Tables_And_Sequences.sql` | Resets the bookstore schema and sequences | Schema owner |
| `COMP214_Full_Team_DDL_Access.sql` | Grants team privileges | Database administrator |
| `COMP214_Team_Private_Synonyms.sql` | Creates shortcuts to shared schema objects | Each teammate |

**Execution tip:** Use **F5 (Run Script)** in Oracle SQL Developer and review the **Script Output** for errors before proceeding to the next step.
